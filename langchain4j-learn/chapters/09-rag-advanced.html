09 · RAG 进阶：查询改写、重排与多路召回

查询转换、多路路由、动态 topK、RRF 聚合与 ScoringModel 重排，以及怎么判断有没有变好。

读完你能做到

  • 用 CompressingQueryTransformer 把多轮追问压成独立问题

  • 把多个 ContentRetriever 路由到同一条 RAG 链路

先说为什么：RAG 进阶是在四个阶段上加策略

DefaultRetrievalAugmentor 的流程是「转换 → 路由并检索 → 聚合 → 注入」， 对应五个可替换组件（检索与路由分开）。基础版大多有默认实现；ContentRetriever 必须由你提供，DefaultQueryRouter 只在调用 builder().contentRetriever(...) 时自动创建。

查询改写：Compressing 与 Expanding

多轮对话里，「那退款呢？」本身信息不足。CompressingQueryTransformer 会结合历史把追问改写成完整问题；ExpandingQueryTransformer 则生成多个变体，提升召回覆盖面。 

QueryTransformer compress = new CompressingQueryTransformer(model);
QueryTransformer expand = new ExpandingQueryTransformer(model, 3);

ExpandingQueryTransformer 默认生成 3 个查询；变体越多，检索次数与延迟越高。

路由：一个还是多个 Retriever

DefaultQueryRouter 把每个查询发给所有 retriever； LanguageModelQueryRouter 则让模型根据 retriever 描述选择一个或多个。 前者稳、后者省，但多一次模型调用。 

ContentRetriever docs = EmbeddingStoreContentRetriever.builder()
        .embeddingStore(docsStore).embeddingModel(embeddingModel).maxResults(4).build();
ContentRetriever tickets = EmbeddingStoreContentRetriever.builder()
        .embeddingStore(ticketStore).embeddingModel(embeddingModel).maxResults(4).build();

QueryRouter router = new DefaultQueryRouter(docs, tickets);

检索参数：动态 topK 与阈值

不同问题需要的召回条数不同。EmbeddingStoreContentRetriever 支持按查询动态决定 maxResults 与 minScore。 

ContentRetriever retriever = EmbeddingStoreContentRetriever.builder()
        .embeddingStore(store)
        .embeddingModel(embeddingModel)
        .dynamicMaxResults(q -> q.text().contains("对比") ? 8 : 4)
        .dynamicMinScore(q -> 0.6)
        .build();

默认 maxResults 是 3、minScore 是 0.0。阈值是检索条件， 由向量库在查询时应用（通常在 LIMIT 之前），所以返回条数可以少于 maxResults，但不是「先取满再过滤」。

聚合与重排：RRF 与 ScoringModel

多路召回会产生重复内容。DefaultContentAggregator 用 RRF（Reciprocal Rank Fusion） 按排名融合；ReRankingContentAggregator 则调用 ScoringModel 对每条内容重新打分。 

ContentAggregator rerank = ReRankingContentAggregator.builder()
        .scoringModel(scoringModel)
        .maxResults(6)
        .build();

重排只对单个查询有默认选择器。如果前面用了 ExpandingQueryTransformer 生成多个查询，必须再传 querySelector(...) 指定用哪个查询打分，否则聚合阶段会抛参数异常。

重排模型可以是 Cohere / Jina 等托管服务，也可以自己实现 ScoringModel。 它会增加一次（或多次）模型调用，适合对精度要求高的场景。

怎么判断有没有变好

不要只看「回答像不像」。至少准备三类样本：答案在文档里、答案不在文档里、需要多跳检索。 然后用 recall@k、MRR、context precision 与人工抽检对比改动前后；没有标注集时，先记录基线再谈优化。

陷阱与窍门

一上来就开改写 + 多查询 + 重排

链路越长越慢也越贵。先用基线定位问题：召回不到、排序不对、还是拼装不好。

多路召回后不去重

同一段内容可能被多次召回；用聚合器融合，别直接全塞进提示词。
