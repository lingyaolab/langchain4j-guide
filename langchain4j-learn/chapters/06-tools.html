06 · Tool Calling：@Tool、上下文与结果

@Tool 参数描述、InvocationContext、ToolExecutionResult、并行调用、异常回传与工具循环。

读完你能做到

  • 用 @Tool 把 Java 方法暴露给模型
  • 用 @P 写清参数语义，降低模型瞎填的概率
  • 用 InvocationContext 读取用户与会话信息
  • 用 ToolExecutionResult 控制成功/失败与返回内容

先说为什么：工具是模型与 Java 的边界

模型只负责「决定调哪个工具、填什么参数」；真正的执行、鉴权、事务都在 Java 侧。 AiServices 会自动完成 schema 生成、工具调用解析、结果回填和下一轮模型调用。

最小可跑：@Tool 与 AiServices

class OrderTools {
    @Tool("按订单号查询订单状态")
    String queryOrder(@P("订单号，例如 SO-20261106-001") String orderNo) {
        return "SHIPPED"; // 真实项目里查数据库
    }
}

interface OrderAssistant {
    String ask(String question);
}

OrderAssistant assistant = AiServices.builder(OrderAssistant.class)
        .chatModel(model)
        .tools(new OrderTools())
        .build();

System.out.println(assistant.ask("帮我查一下 SO-20261106-001"));

@Tool：名字、描述与参数

  • @Tool("...") 是给模型看的描述；不写 name 时使用方法名。
  • @P 写参数含义、格式与示例；模型主要靠它填参。
  • 返回对象会被序列化成 JSON；返回 void 时发送 "Success"。
  • @Tool(returnBehavior = IMMEDIATE) 可以让工具结果直接作为最终回答。

ToolContext：把用户与租户带进工具

1.23 里用 InvocationContext 读取本次调用信息：用户消息、memory id、调用参数等。 它可以作为工具方法参数，由框架注入，不需要模型填。 

@Tool("查询当前用户的订单")
String myOrder(InvocationContext ctx) {
    Object userId = ctx.invocationParameters().get("userId");
    return orderService.findByUser(String.valueOf(userId));
}

ToolResult：成功、失败与直接返回

需要控制结构化结果或错误状态时，返回 ToolExecutionResult： 

@Tool("转账")
ToolExecutionResult transfer(String from, String to, long cents) {
    try {
        bank.transfer(from, to, cents);
        return ToolExecutionResult.builder()
                .resultText("转账成功")
                .build();
    } catch (Exception e) {
        return ToolExecutionResult.builder()
                .isError(true)
                .resultText("转账失败：" + e.getMessage())
                .build();
    }
}

并行工具调用与顺序

模型可能在一轮里返回多个工具调用。框架默认可以并行执行；如果工具有顺序依赖， 应拆成多个工具或让模型分轮调用。不要假设多个工具一定按数组顺序执行。

工具异常怎么回到模型

默认策略是：参数错误可能直接失败；执行异常会把 Tool execution failed: ... 回给模型，让它有机会换方案。 需要自定义时，用 AiServices.toolExecutionErrorHandler(...)。

陷阱与窍门

工具描述写「查询订单」

太短会让模型不知道参数格式；写清「按订单号查状态，返回 SHIPPED/DELIVERED」。

把鉴权交给模型

用户 id、租户 id 必须来自 InvocationContext 或服务端会话，不能让模型填。
