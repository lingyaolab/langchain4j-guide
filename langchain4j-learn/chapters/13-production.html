13 · 生产化：超时、重试、限流与成本

模型超时与重试、并发与限流、降级路由、token 成本、密钥与上线检查清单。

读完你能做到

  • 给模型调用设置合理的连接、读取与流式超时
  • 区分可重试与不可重试错误，避免无效重试
  • 在服务层做限流与降级，而不是把压力全丢给模型
  • 算清 token 成本并守住密钥与工具权限

先说为什么：生产化是在边界上做减法

模型不是数据库：它慢、会限流、输出不确定、按 token 计费。生产化不是加更多功能， 而是给每一次调用加上超时、重试、并发、降级与预算边界。

超时：连接、读取与流式

OpenAiChatModel.builder().timeout(...) 会同时覆盖连接与读取超时； 不设置时连接默认 15 秒、读取默认 60 秒。流式请求可能长时间没有新 token， 读取超时要按场景放宽，别用普通问答的 60 秒。 

ChatModel model = OpenAiChatModel.builder()
        .apiKey(System.getenv("DEEPSEEK_API_KEY"))
        .modelName("deepseek-chat")
        .timeout(Duration.ofSeconds(90))
        .maxRetries(2)
        .build();

重试：哪些错误值得重试

maxRetries 默认是 2，即「首次 + 2 次重试」。429 与 5xx 通常可重试； 400、401、403、404 重试没有意义，只会放大延迟与成本。工具调用还要考虑幂等： 写操作重试前必须确认业务幂等。

并发与限流：别让一个租户打满

  • 在服务入口按租户 / 用户做令牌桶限流（Bucket4j、Resilience4j 都可以）。
  • 给模型调用与工具调用分别设并发上限，避免工具把线程池占满。
  • 流式连接要设置最大生命周期，防止客户端断开后服务端仍长期占用资源。
  • 批量任务走队列，不要在 HTTP 请求里同步跑几十个 Agent。

降级：主模型不可用时怎么办

LangChain4j 没有内置的「主备模型路由」，需要在 ChatModel 外面包一层。 降级模型要能接受同样的消息与参数，并且保留原请求的 maxOutputTokens 等约束。 

final class FallbackChatModel implements ChatModel {
    private final ChatModel primary;
    private final ChatModel fallback;

    @Override
    public ChatResponse doChat(ChatRequest request) {
        try {
            return primary.chat(request);
        } catch (RuntimeException e) {
            log.warn("primary failed, fallback", e);
            return fallback.chat(request);
        }
    }
}

生产环境还应加健康检查、熔断与告警；不要在每次失败后都无限降级。

成本：token、上下文与缓存

  • 从 ChatResponse.tokenUsage() 取输入/输出 token，按模型单价累计。
  • 用 maxOutputTokens 限制回答长度；长回答是成本大头。
  • 控制 RAG topK 与上下文长度；召回越多，输入 token 越高。
  • 对稳定问题做语义缓存或结果缓存，但注意租户隔离与失效策略。

密钥、日志与工具权限

  • API Key 只从环境变量或密钥管理服务读取，不进代码、不进镜像、不进日志。
  • 日志默认不记录完整 prompt / completion；需要时按采样与脱敏开关。
  • 工具白名单最小化；MCP 场景用 filterToolNames(...) 收敛工具面。
  • 工具结果视为不可信输入，不要直接拼 SQL、Shell 或 HTML。

上线检查清单

  1. 超时
    连接、读取、流式分别有上限；流式不沿用短读超时。
  2. 重试
    只重试 429/5xx；写工具确认幂等。
  3. 限流
    入口按租户限流；模型与工具并发分开。
  4. 降级
    主备模型、熔断与告警可演练。
  5. 成本
    token 指标、预算告警、上下文与 topK 有上限。
  6. 安全
    密钥、日志脱敏、工具白名单与最小权限。

陷阱与窍门

把所有错误都重试

401/400 重试只会浪费时间；先分类，再决定重试策略。

只设模型超时，不设工具超时

一个卡住的工具同样会拖垮请求；工具执行也要有边界。

降级模型不兼容参数

主模型支持的参数备用模型未必支持；降级前做能力对齐或裁剪参数。
