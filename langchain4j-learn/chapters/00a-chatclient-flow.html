读源码最容易断片的地方，是「这一步的输出交给了谁」。这一页把 LangChain4j 的一次调用拆成可播放的节点： 从输入、Prompt、ChatRequest，到 ChatModel、工具循环、TokenStream，再到记忆、RAG、MCP 与生产化外围。

这一页怎么用

  • 用 L1 最小场景看清 9 个基础节点，以及每个节点吐出什么
  • 用 L2 工程化场景看新增的 5 个节点：AI Service、记忆、RAG、结构化输出、观测
  • 用 L3 生产化场景看外围节点：Agentic、MCP、Guardrail、Metrics、Judge、部署
  • 用「上一节 / 下一节 / 播放」把信息流走一遍，而不是只看静态图
  • 每一步都能点回对应章节与源码入口

最小链路：一次 call 的 9 个节点

        

          

            
节点它做什么输出给谁

            
              
Input问题字符串或模板变量Prompt

              
Prompt拼 system / user 消息与变量ChatRequest

              
ChatRequest消息 + ChatRequestParametersChatModel

              
ChatModel同步推理，返回 ChatResponse工具循环

              
ToolLoopAI Service 检测工具调用并执行ToolExecution

              
ToolExecution执行 @Tool 方法下一轮上下文

              
ChatModel 2带工具结果再次推理TokenStream

              
TokenStream取文本、POJO 或 SSE 增量调用方

              
OutputHTTP 响应或前端用户

            
          

        


        
工程化：加的 5 个节点

        

          

            
L2 的层插在哪它改变什么

            
              
AI Service +L2最外层用接口声明替代手写 Prompt 与调用

              
ChatMemory +L2Prompt 之前按 memoryId 注入历史消息

              
RAG +L2Prompt 之前检索内容拼进提示词

              
Structured +L2输出之后JSON Schema → POJO / record

              
Listener +L2旁路请求、响应、错误与指标
