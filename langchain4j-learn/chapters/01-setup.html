01 · 环境与依赖：从空目录跑出第一行回答

这一章只做一件事：从空目录开始，装好 JDK 和 Maven，建一个最小工程，拿到第一行模型回答。 不追求讲完所有配置，也不要求你先理解框架设计。每一步都有「怎么验证」，跟着做就行。

学完这一章，你能做什么

  • 用 JDK 17 + Maven 建一个能编译、能运行的 LangChain4j 工程
  • 用 OpenAI 兼容端点（DeepSeek）或本地 Ollama 拿到第一行回答
  • 看懂最小示例里的 5 行关键代码分别负责什么
  • 遇到 401、404、模型名错误时，知道先检查哪一层
这一章不做什么

不展开 AI Service、RAG、工具调用，也不讲 Spring Boot 自动装配。那些是后面章节的事； 这一章的目标只有一个：先让模型回你一句话。

先别急着写代码：LangChain4j 由哪些零件组成

第一次接触 LangChain4j，最容易 confusion 的地方是：它不是「一个 jar」。 它把不同职责拆成模块，你按需引入。先记住三层就够：

你的代码
一个 main 方法，或者后面的 Spring 服务。只依赖接口，不直接依赖某家模型。
LangChain4j 抽象
ChatModel 负责「给消息、返回回答」；UserMessage 等是消息类型； 这些契约在 langchain4j-core。
模型实现
langchain4j-open-ai、langchain4j-ollama 等模块负责真正发 HTTP 请求。 换模型时，通常只换这一层。

所以你会看到两个依赖：langchain4j（AI Service、记忆等常用实现）和 langchain4j-open-ai（OpenAI 兼容模型）。版本交给 BOM 管，不要一个个手写。

第一步：建一个能跑的 Maven 工程

先确认环境。打开终端，执行： 

java -version
mvn -v

期望看到 JDK 17（或更高）和 Maven 3.8+。如果 java -version 显示 8 或 11， 先装 JDK 17；LangChain4j 1.23.0 的编译目标是 17 pom.xml:39。

新建一个目录，写入下面这个 pom.xml：

<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>

  <groupId>demo</groupId>
  <artifactId>first-langchain4j</artifactId>
  <version>1.0</version>

  <properties>
    <maven.compiler.release>17</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    <langchain4j.version>1.23.0</langchain4j.version>
  </properties>

  <dependencyManagement>
    <dependencies>
      <dependency>
        <groupId>dev.langchain4j</groupId>
        <artifactId>langchain4j-bom</artifactId>
        <version>${langchain4j.version}</version>
        <type>pom</type>
        <scope>import</scope>
      </dependency>
    </dependencies>
  </dependencyManagement>

  <dependencies>
    <dependency>
      <groupId>dev.langchain4j</groupId>
      <artifactId>langchain4j</artifactId>
    </dependency>
    <dependency>
      <groupId>dev.langchain4j</groupId>
      <artifactId>langchain4j-open-ai</artifactId>
    </dependency>
  </dependencies>
</project>

验证依赖能解析： 

mvn -q dependency:resolve

没有报错就说明 BOM 和两个模块都下载成功了。BOM 的版本是 1.23.0； 实验模块是 1.23.0-beta33，这一章用不到。

第二步：打出第一行模型回答

建目录 src/main/java/demo，写入 Main.java： 

package demo;

import dev.langchain4j.model.chat.ChatModel;
import dev.langchain4j.model.openai.OpenAiChatModel;

public class Main {
    public static void main(String[] args) {
        ChatModel model = OpenAiChatModel.builder()
                .baseUrl("https://api.deepseek.com/v1")
                .apiKey(System.getenv("DEEPSEEK_API_KEY"))
                .modelName("deepseek-chat")
                .build();

        String answer = model.chat("用一句话解释什么是 RAG");
        System.out.println(answer);
    }
}

设置 API Key（Windows PowerShell）： 

$env:DEEPSEEK_API_KEY = "sk-你的 key"

运行：

mvn -q compile exec:java -Dexec.mainClass=demo.Main

如果输出了一段中文回答，恭喜，第一关过了。没输出也别急，先看下一节的逐行拆解， 再对照「第一次一定会遇到的错误」。

第三步：把这段代码逐行拆开

这 5 行是后面所有章节的地基，值得慢一点看：

  1. ChatModel model
    你在声明「我要一个能对话的模型」，而不是「我要 OpenAI」。 后面换成 Ollama、DashScope，业务代码里的类型仍然是 ChatModel。
  2. baseUrl
    请求发到哪里。OpenAI 兼容端点通常以 /v1 结尾；DeepSeek 的 https://api.deepseek.com 和 .../v1 都能用。 不写时默认是 OpenAI 官方地址。
  3. apiKey
    身份凭证。例子从环境变量读，避免把 key 写进代码。 为空时通常不是 build() 失败，而是第一次请求返回 401。
  4. modelName
    服务端认的模型名。DeepSeek 用 deepseek-chat；Ollama 用 ollama list 里的名字。名字错通常表现为 404 或模型不存在。
  5. model.chat(...)
    最短的同步调用：字符串进、字符串出。它内部会构造一条 user 消息、发请求、 取回 AI 文本。后面我们会换成 ChatRequest 和 AI Service。

第四步：换模型，不改业务代码

现在把 DeepSeek 换成本地 Ollama。先装好 Ollama 并拉一个模型： 

ollama pull qwen3:8b
ollama serve

在 pom.xml 里加一个依赖：

<dependency>
  <groupId>dev.langchain4j</groupId>
  <artifactId>langchain4j-ollama</artifactId>
</dependency>

然后只改构造模型的两行：

ChatModel model = OllamaChatModel.builder()
        .baseUrl("http://localhost:11434")
        .modelName("qwen3:8b")
        .build();

注意：model.chat(...) 和后面的业务代码完全没动。这就是「依赖接口，不依赖厂商」。 下一章会把这条边界讲得更细。

第一次一定会遇到的错误

1. 401 Unauthorized
你会看到
第一次请求就失败，错误里带 401。
因为
API Key 为空、过期，或环境变量没有传进当前终端。
改成
先打印 System.getenv("DEEPSEEK_API_KEY") 是否为空；再确认 key 属于当前 baseUrl 对应的平台。
2. 404 / model not found
你会看到
HTTP 404，或服务端提示模型不存在。
因为
baseUrl 与 modelName 不匹配，或模型名拼错。
改成
对照厂商文档确认完整 URL；Ollama 用 ollama list 看真实模型名。
3. NoSuchMethodError / NoClassDefFoundError
你会看到
编译能过，运行时抛链接错误。
因为
某些模块手写了版本，和 BOM 里的版本对不上。
改成
删掉模块上的 <version>，只保留 BOM 版本。
4. 能编译但运行找不到主类
你会看到
ClassNotFoundException: demo.Main
因为
文件路径和 package demo; 不一致，或 exec:java 的主类写错。
改成
确认文件在 src/main/java/demo/Main.java，并检查 -Dexec.mainClass=demo.Main。

动手练习：做一个命令行问答

把 Main 改成循环读取输入，直到用户输入 exit：

Scanner scanner = new Scanner(System.in);
while (true) {
    System.out.print("你：");
    String input = scanner.nextLine();
    if ("exit".equalsIgnoreCase(input)) break;
    System.out.println("AI：" + model.chat(input));
}

再完成两个小任务：

  1. 把系统提示词改成「你是一个只回答 Java 问题的助手」，观察回答变化。
  2. 把 modelName 改成一个不存在的名字，记录报错信息，再改回来。
做完再往下
