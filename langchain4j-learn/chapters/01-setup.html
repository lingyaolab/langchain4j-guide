先说为什么：LangChain4j 不是一个 jar

它按能力拆成很多模块：langchain4j-core 放契约、数据模型与 RAG 的默认检索/增强实现， langchain4j 放 AI Services、对话记忆实现与文档加载/切分， langchain4j-open-ai 只是其中一个 provider。模块的版本由 BOM 统一管理。

最小可跑：一个 Maven 工程 + 一次 chat

import dev.langchain4j.model.chat.ChatModel;
import dev.langchain4j.model.openai.OpenAiChatModel;

public class Main {
    public static void main(String[] args) {
        ChatModel model = OpenAiChatModel.builder()
                .baseUrl("https://api.deepseek.com/v1")
                .apiKey(System.getenv("DEEPSEEK_API_KEY"))
                .modelName("deepseek-chat")
                .build();

        String answer = model.chat("用一句话解释什么是 RAG");
        System.out.println(answer);
    }
}

模型入口 ChatModel.java:34； OpenAI 构造器 OpenAiChatModel.java:233。

逐行解读：容易懵的地方

  1. baseUrl 不是厂商枚举
    只要对方兼容 OpenAI 的 /chat/completions，就复用 OpenAiChatModel。
  2. apiKey 必须在请求前有值
    为空时通常会在第一次调用时得到 401，而不是 build() 就报错。
  3. modelName 是服务端认的名字
    DeepSeek 用 deepseek-chat；Ollama 用你 ollama list 里的名字。

陷阱与窍门

baseUrl 的 /v1 取决于厂商

因为客户端会在 baseUrl 后拼 /chat/completions；OpenAI 兼容端点通常带 /v1，DeepSeek 的 https://api.deepseek.com 与 .../v1 都可用。改成按厂商文档确认，别把某一家规则套到所有 provider。

把所有模块都写 1.23.0-beta33

因为稳定模块在 BOM 里是 1.23.0。改成只写 BOM 版本，模块不写版本。
