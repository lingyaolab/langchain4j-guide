02 · ChatModel：一次调用从请求到响应

上一章我们只用了 model.chat("一句话")。这一章把这次调用拆开： 消息怎么放、参数怎么传、响应里有什么、流式为什么是另一条接口。 学完你会写一个能连续对话的命令行小助手。

学完这一章，你能做什么

  • 用 ChatRequest 显式组织 system / user 消息
  • 从 ChatResponse 取文本与 token 用量
  • 把同步回答改成流式，并理解回调的执行顺序
  • 写出一个支持多轮输入的命令行助手

先理解：一次模型调用到底发生了什么

先把模型当成一个黑盒函数： 

输入：消息列表 + 参数
  ↓
模型
  ↓
输出：一条 AI 消息 + 用量信息

在 LangChain4j 里，这三段分别对应：

阶段类型你可以控制什么
请求ChatRequest消息、温度、最大输出 token
调用ChatModel同步或流式、用哪个 provider
响应ChatResponse文本、token 用量、工具调用

第一步：用最短代码拿到回答

沿用上一章的工程，先跑最短路径： 

ChatModel model = OpenAiChatModel.builder()
        .baseUrl("https://api.deepseek.com/v1")
        .apiKey(System.getenv("DEEPSEEK_API_KEY"))
        .modelName("deepseek-chat")
        .build();

String answer = model.chat("用三句话解释向量检索");
System.out.println(answer);

chat(String) 是一个便利方法：它把字符串包成一条 user 消息， 再走完整的请求流程。适合验证环境，但不适合多轮或需要 system 提示的场景。

第二步：把这次调用拆成消息与参数

现在不用快捷方法，显式构造请求。你会第一次看到 system 与 user 两种消息： 

ChatRequest request = ChatRequest.builder()
        .messages(
                SystemMessage.from("你是简洁的中文技术编辑，只回答 Java 问题"),
                UserMessage.from("解释 RAG，并给一个 Java 例子"))
        .build();

ChatResponse response = model.chat(request);

System.out.println(response.aiMessage().text());
System.out.println("输入 token：" + response.tokenUsage().inputTokenCount());
System.out.println("输出 token：" + response.tokenUsage().outputTokenCount());

逐段看：

  1. SystemMessage
    告诉模型「你是谁、怎么回答」。它不是用户问题，但会影响整段对话。
  2. UserMessage
    本轮真正的问题。后面多轮对话会有多条 user / AI 消息。
  3. ChatRequest
    把消息和参数装在一起；现在只有消息，参数用默认值。
  4. ChatResponse
    先取 aiMessage()，再取 text()；tokenUsage() 可能为 null。
aiMessage().text() 可能为空

如果模型返回的是工具调用，文本可能为空，内容在 aiMessage().toolExecutionRequests()。 工具章节会展开；现在只需要知道「空回答不一定是 bug」。

第三步：把回答改成流式

同步调用要等整段回答生成完才返回。流式则在每个 token 到达时回调， 更适合聊天 UI。它需要另一个接口：StreamingChatModel。 

StreamingChatModel streamingModel = OpenAiStreamingChatModel.builder()
        .baseUrl("https://api.deepseek.com/v1")
        .apiKey(System.getenv("DEEPSEEK_API_KEY"))
        .modelName("deepseek-chat")
        .build();

ChatRequest request = ChatRequest.builder()
        .messages(UserMessage.from("用 100 字介绍 LangChain4j"))
        .build();

streamingModel.chat(request, new StreamingChatResponseHandler() {
    @Override
    public void onPartialResponse(String token) {
        System.out.print(token);
    }

    @Override
    public void onCompleteResponse(ChatResponse response) {
        System.out.println("\n完成，用量：" + response.tokenUsage());
    }

    @Override
    public void onError(Throwable error) {
        error.printStackTrace();
    }
});

回调顺序是：多次 onPartialResponse → 一次 onCompleteResponse； 出错则走 onError。注意普通 onPartialResponse 不提供取消句柄， 需要取消时用带 context 的重载。

第四步：用 ChatRequest 组织多轮对话

模型本身不记得上一轮。多轮对话的本质是：你每次把历史消息一起发过去。 

List<ChatMessage> history = new ArrayList<>();
history.add(SystemMessage.from("你是 Java 助教，回答控制在 100 字内"));

while (true) {
    System.out.print("你：");
    String input = scanner.nextLine();
    if ("exit".equalsIgnoreCase(input)) break;

    history.add(UserMessage.from(input));
    ChatResponse response = model.chat(ChatRequest.builder()
            .messages(history)
            .build());

    String answer = response.aiMessage().text();
    System.out.println("AI：" + answer);
    history.add(AiMessage.from(answer));
}

这段代码就是「记忆」的雏形。后面第 07 章会用 ChatMemory 替你管理这个列表， 但原理仍然是：把历史消息带进下一次请求。

第五步：控制温度与回答长度

参数通过 ChatRequestParameters 传入。先只学三个最常用的：

参数作用建议
temperature随机性抽取/代码 0–0.3；创意 0.7–1.0
topP采样范围一般 0.9–1.0
maxOutputTokens回答上限按成本和长度设置
 
ChatRequest request = ChatRequest.builder()
        .messages(UserMessage.from("列出三条 RAG 的优点"))
        .parameters(ChatRequestParameters.builder()
                .temperature(0.2)
                .maxOutputTokens(300)
                .build())
        .build();

第六步：换模型，业务代码不动

把 DeepSeek 换成 Ollama，只改构造模型这一段；ChatRequest、 ChatResponse 和循环逻辑都不变。 

ChatModel model = OllamaChatModel.builder()
        .baseUrl("http://localhost:11434")
        .modelName("qwen3:8b")
        .build();

String answer = model.chat("你好，介绍一下你自己");

这就是为什么上一章强调「依赖 ChatModel 接口」。 如果你的业务代码里到处是 OpenAiChatModel，换模型就会变成全量修改。

常见错误与排查

1. 回答是空字符串
你会看到
aiMessage().text() 为空，但请求成功。
因为
模型返回了工具调用，文本部分为空；或者模型只返回了 reasoning 内容。
改成
先检查 toolExecutionRequests()；没有工具调用再看 provider 是否把内容放在别的字段。
2. tokenUsage() 为 null
你会看到
打印用量时 NPE。
因为
不是所有 provider / 模型都会返回用量。
改成
判空后再用，或用 Optional.ofNullable(...) 包一层。
3. 流式没有输出
你会看到
程序结束了，但什么都没打印。
因为
用了 ChatModel 而不是 StreamingChatModel，或回调没实现。
改成
确认类型是 StreamingChatModel，并至少实现 onPartialResponse 与 onError。
4. 多轮对话「失忆」
你会看到
第二轮问「我刚才说了什么」，模型不知道。
因为
每次只发了当前这一条 user 消息。
改成
把之前的 user / AI 消息一起放进 messages，或使用第 07 章的 ChatMemory。

动手练习：多轮命令行助手

把本章代码合成一个小程序，要求：

  1. 启动时设置一条 system 消息：「你是 Java 助教，回答不超过 100 字」。
  2. 循环读取用户输入，输入 exit 退出。
  3. 每轮把历史消息一起发给模型，并把 AI 回答追加进历史。
  4. 给请求设置 temperature(0.3) 与 maxOutputTokens(200)。
  5. 进阶：把同步调用改成流式，观察首字延迟。
