02 · ChatModel：同步、流式与请求对象

ChatModel 与 StreamingChatModel、ChatRequest、ChatResponse、ChatRequestParameters、多模型与 OpenAI 兼容端点。

读完你能做到

  • 区分 ChatModel 与 StreamingChatModel
  • 用 ChatRequest 显式传消息与参数
  • 从 ChatResponse 取文本、token 用量与工具调用
  • 知道什么时候该用流式

先说为什么：ChatModel 与 StreamingChatModel 是两条接口

同步接口返回一个完整的 ChatResponse；流式接口通过回调逐块吐出 StreamingChatResponseHandler 事件。两者不是继承关系，很多 provider 会同时实现。

ChatModel.java:34 StreamingChatModel.java:41

最小可跑：chat 与 chatRequest

// 1) 最省事：字符串进，字符串出
String text = model.chat("用三句话解释向量检索");

// 2) 显式请求：消息 + 参数
ChatRequest request = ChatRequest.builder()
        .messages(SystemMessage.from("你是简洁的中文技术编辑"),
                  UserMessage.from("解释 RAG，并给一个 Java 例子"))
        .parameters(ChatRequestParameters.builder()
                .temperature(0.2)
                .maxOutputTokens(800)
                .build())
        .build();

ChatResponse response = model.chat(request);
System.out.println(response.aiMessage().text());
System.out.println(response.tokenUsage());

请求对象 ChatRequest.java:15； 响应对象 ChatResponse.java:11。

逐行解读：消息、参数与返回值

  • SystemMessage 是行为约束，UserMessage 是本轮输入。
  • ChatRequestParameters 是接口，DefaultChatRequestParameters 是通用实现。
  • aiMessage().text() 只取文本；如果模型返回工具调用，文本可能为空。
  • tokenUsage() 可能为 null，取决于 provider 是否返回用量。

同步与流式：什么时候用哪个

场景用哪个原因
批处理、后台任务同步代码简单，错误直接抛
聊天 UI、SSE流式首字延迟低，可提前取消
需要工具循环AI Service框架替你处理多轮工具往返

ChatRequest：把消息与参数装进一个对象

ChatRequest 是 builder 模式：messages(...) 可以传列表或可变参数， parameters(...) 接收 ChatRequestParameters。 这样同一份参数可以复用到多次调用。 

ChatRequestParameters params = ChatRequestParameters.builder()
        .temperature(0.0)
        .topP(0.9)
        .maxOutputTokens(400)
        .build();

ChatResponse a = model.chat(ChatRequest.builder()
        .messages(UserMessage.from("列出三条 RAG 优点"))
        .parameters(params)
        .build());

ChatRequestParameters：温度、topP、maxOutputTokens

参数作用常见取值
temperature随机性抽取 0–0.3；创意 0.7–1.0
topP nucleus 采样一般 0.9–1.0
maxOutputTokens回答上限按成本与长度设

多模型与 OpenAI 兼容端点

只要协议兼容，就可以用同一个 OpenAiChatModel 接不同厂商；差异主要在 baseUrl、modelName 和部分扩展参数。多模型场景建议把 ChatModel 作为构造器参数注入，而不是在业务代码里 new。

API 速查

方法用途
model.chat(String)最短路径
model.chat(ChatMessage...)多消息
model.chat(ChatRequest)带参数
response.aiMessage().text()取文本
response.tokenUsage()取用量

陷阱与窍门

把 ChatModel 当线程安全单例随便共享

多数实现是无状态的，但要确认 provider 文档；有状态实现应按请求创建或加锁。

流式接口也返回 ChatResponse

它通过回调聚合最终响应；不要以为流式只有字符串。
