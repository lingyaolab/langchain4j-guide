先说为什么：MCP 是工具协议，不是框架

MCP 把「工具、资源、提示词」抽象成标准协议。LangChain4j 提供的是客户端 （langchain4j-mcp）；Java 服务端用社区模块 langchain4j-community-mcp-server。两者都只是协议实现，不绑定模型或编排方式。

传输：stdio、Streamable HTTP 与 Docker

stdio 适合本地子进程：客户端启动 Server 进程，通过标准输入输出交换 JSON-RPC。 Streamable HTTP 适合独立服务：客户端向一个 URL 发请求，需要时由 Server 打开 SSE 流。 

McpTransport transport = StdioMcpTransport.builder()
        .command(List.of("npx", "-y", "@modelcontextprotocol/server-everything"))
        .logEvents(true)
        .build();
McpTransport transport = StreamableHttpMcpTransport.builder()
        .url("http://localhost:3001/mcp")
        .logRequests(true)
        .logResponses(true)
        .build();

另有 WebSocket 传输（非标准，兼容 Quarkus MCP）与 Docker stdio 传输 （langchain4j-mcp-docker）。

MCP Client：连接、协议版本与超时

DefaultMcpClient 用 transport 创建连接。默认会自动探测协议版本， 优先现代无状态协议；已知服务端版本时，显式 protocolVersion(...) 可省一次往返。 

McpClient mcpClient = DefaultMcpClient.builder()
        .key("everything")
        .transport(transport)
        .initializationTimeout(Duration.ofSeconds(30))
        .build();

多客户端时 key 很重要：工具重名时用它区分来源，日志里也靠它定位。

McpToolProvider：过滤、改名与多 Server

McpToolProvider 把 MCP 工具转成 LangChain4j 的 ToolProvider。 它可以接多个客户端，并按名字或谓词过滤，避免把几十个工具全塞给模型。 

McpToolProvider toolProvider = McpToolProvider.builder()
        .mcpClients(mcpClient)
        .filterToolNames("get_issue", "get_issue_comments", "list_issues")
        .failIfOneServerFails(false)
        .build();

Assistant assistant = AiServices.builder(Assistant.class)
        .chatModel(model)
        .toolProvider(toolProvider)
        .build();

多 Server 工具重名时，用 toolNameMapper(...) 给逻辑名加前缀； 注意过滤发生在改名之前，白名单要写 Server 返回的原始名。

Java MCP Server：用 @Tool 暴露能力

Java 服务端不在 langchain4j-mcp 里，而在社区模块 langchain4j-community-mcp-server。仍然用 @Tool 写方法， 再由 McpServer + StdioMcpServerTransport 启动。 

McpImplementation serverInfo = new McpImplementation();
serverInfo.setName("my-java-mcp-server");
serverInfo.setVersion("1.0.0");

McpServer server = new McpServer(List.of(new Calculator()), serverInfo);
new StdioMcpServerTransport(System.in, System.out, server);

Thread.currentThread().join();

参数名来自 Java 方法参数名，所以编译时必须开 -parameters；否则客户端看到的是 arg0、arg1。

安全与治理：白名单、密钥与日志

  • 默认只暴露需要的工具：filterToolNames(...) 或 filter(...)。
  • 在 HTTP 传输上通过 header 传 API Key，不要把密钥写进工具参数。
  • 工具结果视为不可信输入，不要直接拼进 SQL、Shell 或 HTML。
  • stdio Server 的日志必须写 System.err；写 System.out 会破坏 JSON-RPC。
  • 给初始化、工具执行与资源读取分别设超时，避免一个慢 Server 拖住整条链路。

陷阱与窍门

stdio Server 往 stdout 打日志

协议流被污染，客户端会断开。所有日志改到 stderr。

没开 -parameters

工具参数名变成 arg0，模型填参质量会明显下降。

把整个 MCP Server 的工具全暴露

工具越多，模型越容易选错；用白名单 + 清晰描述收敛工具面。
