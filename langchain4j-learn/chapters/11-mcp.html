11 · MCP：把工具放到另一个进程

上一章的工具和 Agent 在同一个 JVM 里。MCP 把工具挪到另一个进程： 可以是本地子进程，也可以是远程服务。这样同一套工具能被多个应用复用。 这一章先连一个现成 Server，再把自己的 @Tool 暴露出去。

学完这一章，你能做什么

  • 用 stdio 或 Streamable HTTP 连上一个 MCP Server
  • 用 McpToolProvider 过滤工具并接进 AI Service
  • 用社区模块把自己的 @Tool 暴露成 MCP Server
  • 知道 MCP 的安全边界与常见协议坑

先理解：为什么工具要放到另一个进程

本地 @Tool 有三个限制：只能在这个 JVM 里用；升级工具要重新部署应用； 不同语言的应用无法复用。MCP 把工具做成标准协议，谁都能连：

方式工具在哪适合
本地 @Tool同一个 JVM业务内部方法、低延迟
MCP stdio本地子进程桌面工具、CLI、单机应用
MCP HTTP远程服务多应用共享、独立部署

LangChain4j 提供 MCP 客户端；Java 服务端用社区模块 langchain4j-community-mcp-server。

第一步：选传输方式

stdio 适合本地子进程：客户端启动 Server，通过标准输入输出交换 JSON-RPC。 

McpTransport transport = StdioMcpTransport.builder()
        .command(List.of("npx", "-y", "@modelcontextprotocol/server-everything"))
        .logEvents(true)
        .build();

Streamable HTTP 适合远程服务：客户端向一个 URL 发请求，需要时由 Server 打开 SSE 流。 

McpTransport transport = StreamableHttpMcpTransport.builder()
        .url("http://localhost:3001/mcp")
        .logRequests(true)
        .logResponses(true)
        .build();

还有 WebSocket（非标准，兼容 Quarkus MCP）与 Docker stdio（ langchain4j-mcp-docker）。

第二步：连上一个 MCP Server

McpClient mcpClient = DefaultMcpClient.builder()
        .key("everything")
        .transport(transport)
        .build();

key 在多客户端场景很重要：工具重名时用它区分来源，日志里也靠它定位。 客户端默认自动探测协议版本；已知服务端版本时，可以显式设置 protocolVersion， 省掉一次探测往返。

第三步：把 MCP 工具接进 AI Service

MCP 工具不会自动进入 AI Service，需要 McpToolProvider 转一层。 一个 provider 可以接多个客户端，并按名字或谓词过滤： 

McpToolProvider toolProvider = McpToolProvider.builder()
        .mcpClients(mcpClient)
        .filterToolNames("get_issue", "get_issue_comments", "list_issues")
        .failIfOneServerFails(false)
        .build();

SupportAssistant assistant = AiServices.builder(SupportAssistant.class)
        .chatModel(model)
        .toolProvider(toolProvider)
        .build();

多 Server 工具重名时，用 toolNameMapper 给逻辑名加前缀。 注意过滤发生在改名之前，白名单要写 Server 返回的原始名。

McpToolProvider.java:234 AiServices.java:537

第四步：把自己的 @Tool 暴露成 MCP Server

Java 服务端用社区模块，仍然用 @Tool 写方法： 

McpImplementation serverInfo = new McpImplementation();
serverInfo.setName("my-java-mcp-server");
serverInfo.setVersion("1.0.0");

McpServer server = new McpServer(List.of(new Calculator()), serverInfo);
new StdioMcpServerTransport(System.in, System.out, server);

Thread.currentThread().join();

MCP 工具参数名来自 Java 方法参数名，所以编译时必须开 -parameters； 否则客户端看到的是 arg0、arg1。

mcp-stdio-server.md:44 mcp-stdio-server.md:98

第五步：白名单、密钥与日志

  • 默认只暴露需要的工具：filterToolNames(...) 或 filter(...)。
  • HTTP 传输用 header 传 API Key，不要把密钥写进工具参数。
  • 工具结果视为不可信输入，不要直接拼 SQL、Shell 或 HTML。
  • stdio Server 的日志必须写 System.err；写 System.out 会破坏 JSON-RPC。
  • 给初始化、工具执行与资源读取分别设超时，避免一个慢 Server 拖住整条链路。

常见错误与排查

1. 客户端连上但工具列表为空
你会看到
listTools() 返回空。
因为
Server 没暴露工具、白名单过滤掉了，或客户端 key 冲突。
改成
先不加过滤打印全部工具；检查 Server 端 @Tool 是否注册。
2. stdio Server 一启动就断开
你会看到
客户端报协议解析错误。
因为
Server 把日志写到了 stdout，污染了 JSON-RPC 流。
改成
所有日志改到 stderr。
3. 参数名变成 arg0 / arg1
你会看到
模型填参质量明显下降。
因为
编译时没开 -parameters。
改成
在 maven-compiler-plugin 里设 <parameters>true</parameters>。
4. 远程 Server 请求超时
你会看到
初始化或工具调用卡住。
因为
HTTP 客户端读超时太短，或 Server 端 SSE 长时间无数据。
改成
放宽读超时，分别设置初始化/工具/资源超时。

动手练习：本地工具 + 远程 Server

  1. 用 server-everything 跑通 stdio 客户端，打印全部工具。
  2. 只保留 2–3 个工具，接进 AI Service，问一个需要工具的问题。
  3. 用自己的 @Tool 写一个 Java MCP Server，用 .mcp.json 配到客户端。
  4. 故意让 Server 往 stdout 打日志，观察客户端如何报错。
  5. 进阶：起一个 Streamable HTTP Server，改用 URL 连接。
