03 · Prompt 与消息：从一条消息到可维护的提示词

上一章我们把消息直接写在代码里。这一章解决两个问题： 第一，为什么要用「消息列表」而不是一段字符串；第二，怎么把提示词变成可以维护、可以复用、 可以带变量的模板。最后会做一个带系统提示的客服助手。

学完这一章，你能做什么

  • 说清 System / User / AI / Tool / Custom 五类消息各自负责什么
  • 用 PromptTemplate 管理提示词变量，知道变量缺失会怎样
  • 把图片作为用户消息的一部分发出去
  • 写一个带系统提示、模板变量和日期注入的客服助手

先理解：提示词不是一段话，而是一组角色消息

很多人第一次写提示词，会写成一个大字符串： 

你是客服。用户问：我的订单到哪了？请只回答订单状态。

这样能跑，但很快会遇到三个问题：

  • 系统约束和用户问题混在一起，模型容易把「客服规则」当成用户说的话。
  • 多轮对话时，历史消息无法区分谁说的。
  • 工具结果需要作为单独角色回填，字符串模型无法表达。

所以 LangChain4j 的模型接口接收的是 List<ChatMessage>。 字符串只是 chat(String) 的快捷方式，背后仍然会包成一条 user 消息。

第一步：认识五类消息

类型谁产生典型用途
SystemMessage应用角色、规则、输出格式
UserMessage用户 / 应用本轮问题，可带文本、图片
AiMessage模型回答或工具调用请求
ToolExecutionResultMessage应用 / AI Service工具执行结果，回填给模型
CustomMessage应用带任意属性的自定义消息，需 provider 支持

先写一个最小的两角色对话： 

List<ChatMessage> messages = List.of(
        SystemMessage.from("你是电商客服，回答不超过 80 字，不编造订单信息"),
        UserMessage.from("我的订单 SO-20261106-001 到哪了？")
);

ChatResponse response = model.chat(ChatRequest.builder()
        .messages(messages)
        .build());

注意消息顺序：system 通常在最前，然后是历史 user / AI 消息，最后才是本轮 user。 模型不会自己整理顺序，顺序错了，回答也会怪。

第二步：把提示词变成可维护的模板

直接把提示词写在 Java 字符串里，改一次就要重新编译；同一个提示词在多处复制，很容易不一致。 模板解决的是「变量替换」这件事： 

PromptTemplate template = PromptTemplate.from("""
        你是{{role}}。
        回答要求：{{style}}。
        用户问题：{{question}}
        """);

Prompt prompt = template.apply(Map.of(
        "role", "电商客服",
        "style", "不超过 80 字，不编造订单信息",
        "question", "我的订单 SO-20261106-001 到哪了？"
));

UserMessage userMessage = prompt.toUserMessage();
ChatResponse response = model.chat(userMessage);

模板只认 {{name}} 这种双花括号。单个花括号是普通字符，写 JSON 示例不需要转义。 变量缺失时不会静默留空，而是直接抛 IllegalArgumentException。

第三步：变量、默认值与运行时参数

这里要分清两个东西：

名字放在哪例子
模板变量PromptTemplate.apply(Map){{role}}、{{question}}
运行时参数ChatRequestParameterstemperature、maxOutputTokens

模板本身没有「默认值语法」。想给默认值，在 Java 侧处理： 

Map<String, Object> vars = new HashMap<>();
vars.put("role", role == null ? "电商客服" : role);
vars.put("style", "不超过 80 字");
vars.put("question", question);

Prompt prompt = PromptTemplate.from("""
        你是{{role}}。今天是{{current_date}}。
        回答要求：{{style}}。
        用户问题：{{question}}
        """).apply(vars);

current_date、current_time、current_date_time 是框架自动注入的特殊变量，不需要你手动传。

运行时参数则在请求上设置，和模板变量互不影响： 

ChatRequest request = ChatRequest.builder()
        .messages(prompt.toUserMessage())
        .parameters(ChatRequestParameters.builder()
                .temperature(0.2)
                .maxOutputTokens(300)
                .build())
        .build();

第四步：让用户发图片

UserMessage 不只能装字符串。把文本和图片作为 Content 一起放进去： 

UserMessage message = UserMessage.from(
        TextContent.from("这张图里是什么错误？"),
        ImageContent.from("https://example.com/error.png")
);

ChatResponse response = model.chat(message);

图片是否可用取决于模型与 provider；不支持时通常会在 HTTP 层报参数错误。 本地文件可以先转成 base64 再传给 ImageContent.from(...)。

常见错误与排查

1. 模板变量缺失
你会看到
IllegalArgumentException: Value for the variable 'role' is missing
因为
模板里写了 {{role}}，但 apply(Map) 没传这个键。
改成
补齐 Map；需要默认值时在 Java 侧用 getOrDefault。
2. 把 JSON 的花括号转义了
你会看到
输出里出现反斜杠，或模板变量没替换。
因为
模板只认 {{name}}，单花括号不需要转义。
改成
JSON 原样写；要输出字面 {{...}}，把它作为变量值传入。
3. system 消息没生效
你会看到
模型没有遵守角色设定。
因为
provider 忽略 system 角色，或 system 消息不在列表开头。
改成
把 system 放最前；关键约束在 user 消息里再强调一次。
4. 图片请求 400
你会看到
HTTP 400，提示不支持的 content 类型。
因为
当前模型/端点不支持图片输入。
改成
换支持视觉的模型，或把图片先转成文字描述再发。

动手练习：带系统提示的客服助手

把本章内容合成一个客服小助手，要求：

  1. 用 PromptTemplate 管理 system 提示，角色是「电商客服」。
  2. 用户问题里带订单号，模板变量 {{orderNo}} 注入。
  3. system 提示里带 {{current_date}}，让模型知道今天日期。
  4. 给请求设置 temperature(0.2) 与 maxOutputTokens(200)。
  5. 进阶：如果用户输入以 image: 开头，把后面的 URL 作为图片发出去。
