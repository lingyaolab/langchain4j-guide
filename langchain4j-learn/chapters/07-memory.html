07 · Memory：窗口、存储与多用户隔离

MessageWindowChatMemory、ChatMemoryStore、窗口淘汰、多会话与持久化。

读完你能做到

  • 用 MessageWindowChatMemory 控制上下文长度
  • 用 ChatMemoryStore 把消息落到 Redis 或数据库
  • 用 @MemoryId 做多用户隔离
  • 知道窗口淘汰时哪些消息会被保留

先说为什么：记忆是消息窗口，不是数据库

LangChain4j 的 ChatMemory 负责「本次请求要带哪些历史消息」； 真正的持久化由 ChatMemoryStore 完成。两者分开，方便你换存储而不改业务。

MessageWindowChatMemory：窗口与淘汰

ChatMemory memory = MessageWindowChatMemory.withMaxMessages(20);

Assistant assistant = AiServices.builder(Assistant.class)
        .chatModel(model)
        .chatMemory(memory)
        .build();

窗口大小必须显式设置：withMaxMessages(n) 或 builder().maxMessages(n)。不设置时构造函数会因 maxMessagesProvider 为空而失败。

ChatMemoryStore：内存、Redis 与自定义

ChatMemoryStore 只有三个核心方法：读取、更新、删除某个 memoryId 的消息列表。 实现它就能接 Redis、JDBC 或对象存储。 

class RedisChatMemoryStore implements ChatMemoryStore {
    public List<ChatMessage> getMessages(Object memoryId) { ... }
    public void updateMessages(Object memoryId, List<ChatMessage> messages) { ... }
    public void deleteMessages(Object memoryId) { ... }
}

ChatMemoryAccess 与多轮调用

AI Service 每次调用会自动读取记忆、追加本轮消息、再把 AI 回答写回。 你不需要手动维护消息列表；需要清空时通过 ChatMemory.clear() 或删除 store 中的键。

多用户、多会话与隔离

interface Assistant {
    String chat(@MemoryId String userId, @UserMessage String message);
}

Assistant assistant = AiServices.builder(Assistant.class)
        .chatModel(model)
        .chatMemoryProvider(id -> MessageWindowChatMemory.withMaxMessages(20))
        .build();

@MemoryId 的值会传给 ChatMemoryProvider；生产环境建议用 tenantId + ":" + userId，避免不同租户撞键。

持久化与重启恢复

进程内记忆会随重启丢失。要恢复，必须把消息写进外部 store，并保证同一个 memoryId 在重启后仍能查到。注意消息对象的 JSON 兼容性，升级版本时先做回归。

陷阱与窍门

窗口设得太大

历史全部塞进上下文会推高成本与延迟；20–50 条通常够用，长对话靠摘要而不是无限窗口。

memoryId 用随机 UUID

每次请求都换 id 等于没有记忆；要用稳定的会话键。
