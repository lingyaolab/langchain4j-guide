04 · AI Services：声明式接口与注解

AiServices.create、接口方法契约、@SystemMessage / @UserMessage / @V、记忆与工具接入、TokenStream。

读完你能做到

  • 用一个 Java 接口描述 AI 能力，而不是到处拼 ChatRequest
  • 用注解绑定系统提示词、用户模板与变量
  • 把记忆与工具挂到同一个 AI Service 上
  • 知道流式接口为什么返回 TokenStream

先说为什么：AI Services 是声明式门面

它把「构造消息 → 调模型 → 解析结果 → 处理工具循环」收进一个动态代理。 你只写接口，框架在运行时生成实现。复杂逻辑仍然可以退回手写 ChatModel。

最小可跑：一个接口 + AiServices.create

interface Assistant {
    @SystemMessage("你是简洁的中文技术编辑，只回答 Java 问题")
    @UserMessage("解释 {{topic}}，不超过 100 字")
    String explain(@V("topic") String topic);
}

Assistant assistant = AiServices.create(Assistant.class, model);
System.out.println(assistant.explain("虚拟线程"));

入口 AiServices.java:194； builder AiServices.java:218。

接口契约：方法名、参数与返回值

  • 一个方法就是一次调用；参数默认按顺序作为用户消息的一部分。
  • 返回值决定解析方式：String、POJO、List<T>、enum 等。
  • 方法可以抛运行时异常；模型/网络错误会从代理里抛出。

常用注解：@SystemMessage、@UserMessage、@V

注解作用
@SystemMessage固定系统提示词，可引用模板变量
@UserMessage用户消息模板
@V把方法参数绑定到模板变量
@MemoryId指定多用户记忆的会话键

把 ChatMemory 接进 AI Service

Assistant assistant = AiServices.builder(Assistant.class)
        .chatModel(model)
        .chatMemory(MessageWindowChatMemory.withMaxMessages(20))
        .build();

String a = assistant.chat("我叫小明");
String b = assistant.chat("我叫什么？");

单用户可以用一个 ChatMemory；多用户用 chatMemoryProvider(memoryId -> ...)，并在方法参数上标 @MemoryId。

把工具接进 AI Service

class Calculator {
    @Tool("计算两个整数之和")
    int add(int a, int b) { return a + b; }
}

Assistant assistant = AiServices.builder(Assistant.class)
        .chatModel(model)
        .tools(new Calculator())
        .build();

框架会自动生成工具 schema、执行工具、把结果回填，并继续模型循环。你不需要手写 tool_calls 的解析。

流式与 TokenStream

interface StreamingAssistant {
    TokenStream chat(String message);
}

TokenStream stream = streamingAssistant.chat("写一段 Java 并流式输出");
stream.onPartialResponse(System.out::print)
      .onCompleteResponse(r -> System.out.println("\n完成"))
      .start();

API 速查

需求写法
最快创建AiServices.create(Assistant.class, model)
加记忆.chatMemory(...) / .chatMemoryProvider(...)
加工具.tools(object...)
加 RAG.contentRetriever(...)
流式返回 TokenStream

陷阱与窍门

接口方法名乱写

方法名会出现在日志与可观测性里；用业务语义命名，别用 doIt。

把复杂分支全塞进一个接口

AI Service 适合稳定契约；多步编排、重试与人工审批应放在上层服务。
