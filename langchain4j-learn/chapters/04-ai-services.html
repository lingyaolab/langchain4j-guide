04 · AI Services：把一次调用收进一个接口

前两章我们一直在手写 ChatRequest。这一章换一种方式：把「问什么、怎么问、带什么记忆、 能用什么工具」写成一个 Java 接口，让框架生成实现。你会先写一个最小接口，再逐步加上记忆、 工具和流式，最后做一个能查订单的客服助手。

学完这一章，你能做什么

  • 用 AiServices.create 写出第一个 AI Service
  • 理解方法参数、返回值与注解的映射规则
  • 给 AI Service 接上记忆，做多轮对话
  • 给 AI Service 接上工具，让模型查业务数据
  • 把同步接口改成流式接口

先理解：为什么要把调用收进一个接口

上一章的代码大致是这样： 

ChatRequest request = ChatRequest.builder()
        .messages(
                SystemMessage.from("你是电商客服"),
                UserMessage.from("订单 " + orderNo + " 到哪了？"))
        .parameters(ChatRequestParameters.builder().temperature(0.2).build())
        .build();
ChatResponse response = model.chat(request);

只有一次调用还好。一旦有十个业务场景，你会得到十个几乎一样的请求构造块： 系统提示重复、参数重复、消息拼接重复。AI Service 把这些重复收进接口： 

interface SupportAssistant {
    @SystemMessage("你是电商客服")
    @UserMessage("订单 {{orderNo}} 到哪了？")
    String ask(@V("orderNo") String orderNo);
}

你只写「业务上问什么」，框架负责构造消息、调用模型、解析返回值。 底层仍然是 ChatModel，只是多了一层代理。

第一步：写第一个 AI Service

interface SupportAssistant {
    @SystemMessage("你是电商客服，回答不超过 80 字")
    @UserMessage("订单 {{orderNo}} 到哪了？")
    String ask(@V("orderNo") String orderNo);
}

SupportAssistant assistant = AiServices.create(SupportAssistant.class, model);
String answer = assistant.ask("SO-20261106-001");
System.out.println(answer);

跑通之后，先确认三件事：

  • AiServices.create 的第二个参数是 ChatModel，不是模型名字符串。
  • 接口方法可以没有实现，框架会在运行时生成代理。
  • 返回类型是 String，所以框架直接把 AI 文本给你。

第二步：方法参数与返回值怎么映射

这里有一条新手最容易踩的规则：

只有一个无注解参数时，它才会自动变成用户消息

如果有多个参数，必须用 @UserMessage + @V 明确告诉框架 哪个参数填哪个变量，否则会报「没有定义用户消息」。 

interface SupportAssistant {
    @SystemMessage("你是电商客服")
    @UserMessage("用户 {{userId}} 问订单 {{orderNo}} 的状态")
    String ask(@V("userId") String userId,
               @V("orderNo") String orderNo);
}

返回值也不只支持 String：

返回类型框架怎么处理
String直接取 AI 文本
POJO / record按 JSON Schema 解析成对象（下一章展开）
TokenStream返回流式句柄，不阻塞
Result<T>同时拿到内容和工具执行记录

第三步：用注解管系统提示与变量

注解放在哪作用
@SystemMessage方法或接口固定系统提示，可含 {{var}}
@UserMessage方法或参数用户消息模板
@V方法参数把参数绑定到模板变量
@MemoryId方法参数指定多用户记忆的会话键

一个常见组合：系统提示放接口上，用户模板放方法上，变量用 @V 绑定。

第四步：接上记忆，做多轮助手

上一章我们手动维护历史列表。现在把这件事交给 ChatMemory： 

SupportAssistant assistant = AiServices.builder(SupportAssistant.class)
        .chatModel(model)
        .chatMemory(MessageWindowChatMemory.withMaxMessages(20))
        .build();

System.out.println(assistant.ask("我叫小明"));
System.out.println(assistant.ask("我叫什么？"));

多用户场景用 chatMemoryProvider，并在方法参数上标 @MemoryId： 

interface SupportAssistant {
    String ask(@MemoryId String userId, @UserMessage String question);
}

SupportAssistant assistant = AiServices.builder(SupportAssistant.class)
        .chatModel(model)
        .chatMemoryProvider(id -> MessageWindowChatMemory.withMaxMessages(20))
        .build();

第五步：接上工具，让模型查数据

记忆解决「记得住」，工具解决「查得到」。给客服加一个订单查询工具： 

class OrderTools {
    @Tool("按订单号查询订单状态，只读")
    String queryOrder(@P("订单号，例如 SO-20261106-001") String orderNo) {
        return orderService.statusOf(orderNo);
    }
}

SupportAssistant assistant = AiServices.builder(SupportAssistant.class)
        .chatModel(model)
        .chatMemory(MessageWindowChatMemory.withMaxMessages(20))
        .tools(new OrderTools())
        .build();

System.out.println(assistant.ask("帮我查一下 SO-20261106-001"));

框架会自动做三件事：把 @Tool 方法转成模型能看懂的 schema、 解析模型返回的工具调用、执行工具后把结果回填给模型继续推理。 你不需要手写 tool_calls 的解析。

第六步：改成流式接口

把返回类型改成 TokenStream，并给 builder 配 streamingChatModel。 注意：同一个 AI Service 不能同时配同步和流式模型。 

interface StreamingAssistant {
    @SystemMessage("你是电商客服")
    TokenStream ask(@UserMessage String question);
}

StreamingAssistant assistant = AiServices.builder(StreamingAssistant.class)
        .streamingChatModel(streamingModel)
        .build();

TokenStream stream = assistant.ask("介绍一下退货政策");
stream.onPartialResponse(System.out::print)
      .onCompleteResponse(r -> System.out.println("\n完成"))
      .onError(Throwable::printStackTrace)
      .start();

常见错误与排查

1. does not have a user message defined
你会看到
启动或首次调用时抛配置异常。
因为
方法有多个参数，但没有 @UserMessage 或 @V。
改成
加 @UserMessage 模板，并用 @V 绑定每个参数。
2. 同时配了 chatModel 与 streamingChatModel
你会看到
配置异常：either chatModel or streamingChatModel should be configured。
因为
框架要求二选一。
改成
同步接口只配 chatModel；返回 TokenStream 的接口只配 streamingChatModel。
3. 模型不调用工具
你会看到
回答正常，但工具没执行。
因为
工具描述太模糊，或模型不支持 function calling。
改成
把 @Tool 描述写清「什么时候用、输入是什么、返回什么」。
4. 多轮对话串用户
你会看到
A 用户看到 B 用户的历史。
因为
所有请求共用一个 ChatMemory。
改成
用 chatMemoryProvider + @MemoryId 按用户隔离。

动手练习：客服助手升级

  2. 用 @MemoryId 按用户隔离记忆。
  3. 接一个 OrderTools，能按订单号查状态。
  4. 把其中一个方法改成流式，观察首字延迟。
  5. 进阶：给系统提示加 {{current_date}}，让回答能说「今天」。
