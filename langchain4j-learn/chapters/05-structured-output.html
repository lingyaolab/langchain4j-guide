先说为什么：结构化输出不是 prompt 技巧

在 LangChain4j 里，返回类型就是契约：AiServices 会为 POJO / record 生成 JSON Schema，要求模型按 schema 输出，再把 JSON 解析成对象。你不需要手写 「请返回 JSON」这段提示词。

JSON Schema：让模型知道字段

ServiceOutputParser.jsonSchema(Type) 负责从返回类型推导 schema； outputFormatInstructions(Type) 生成给模型的格式说明。

POJO 与 record：返回值映射

record Movie(String title, int year, List<String> genres) {}

interface MovieAssistant {
    @UserMessage("推荐一部 {{genre}} 电影，返回 JSON")
    Movie recommend(@V("genre") String genre);
}

MovieAssistant assistant = AiServices.create(MovieAssistant.class, model);
Movie movie = assistant.recommend("科幻");
System.out.println(movie.title() + " / " + movie.year());

枚举、列表与嵌套对象

  • 枚举字段会生成 enum 约束；模型给出不在枚举里的值会解析失败。
  • List<T> / Set<T> 会生成数组 schema。
  • 嵌套 record 会递归生成对象 schema；避免循环引用。

校验与失败重试

框架负责「JSON → 对象」的解析，但业务校验（金额为正、日期范围）仍要你自己做。 常见做法是校验失败后把错误信息拼回下一轮请求，让模型修正；注意设置最大重试次数，避免无限循环。

模型返回 markdown 代码围栏

部分模型会包一层 markdown 代码围栏；解析器通常能处理，但最好在系统提示里明确「只输出 JSON」。

流式结构化输出

流式场景下，部分 token 不是完整 JSON，不能边收边解析成对象。要么先聚合完整响应再解析， 要么让接口返回 TokenStream，在 onCompleteResponse 里处理最终对象。

陷阱与窍门

字段名和业务含义不一致

模型按字段名与描述生成内容；用 @JsonPropertyDescription 补语义，别用 f1、f2。

把校验失败当异常吞掉

要么重试，要么把错误交给上层；静默返回 null 会让问题更难查。
