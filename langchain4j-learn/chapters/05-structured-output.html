05 · 结构化输出：让接口直接返回对象

上一章的 AI Service 返回字符串。业务代码真正想要的是对象：订单、电影、分类结果。 这一章从「让接口返回一个 record」开始，逐步理解 JSON Schema、嵌套对象、业务校验， 以及为什么流式场景不能直接返回对象。

学完这一章，你能做什么

  • 让 AI Service 直接返回 record / POJO，而不是自己解析 JSON
  • 理解框架什么时候用 JSON Schema，什么时候退回提示词格式说明
  • 处理列表、枚举与嵌套对象
  • 知道解析失败、业务校验失败与流式场景分别该怎么处理

先理解：为什么需要让模型返回对象

假设你要推荐电影。返回字符串时，业务代码要自己解析： 

推荐《流浪地球》，2023 年，科幻 / 冒险。

解析器要处理中文书名号、年份位置、分隔符，模型换个说法就崩。 更好的方式是把「返回什么」定义成 Java 类型： 

record Movie(String title, int year, List<String> genres) {}

AI Service 的返回类型就是契约。框架会要求模型按这个结构输出，再把 JSON 映射成对象。 你拿到的是 Movie，不是一段待解析文本。

第一步：让接口返回一个 record

record Movie(String title, int year, List<String> genres) {}

interface MovieAssistant {
    @UserMessage("推荐一部{{genre}}电影，返回标题、年份和类型")
    Movie recommend(@V("genre") String genre);
}

MovieAssistant assistant = AiServices.create(MovieAssistant.class, model);
Movie movie = assistant.recommend("科幻");

System.out.println(movie.title());
System.out.println(movie.year());
System.out.println(movie.genres());

运行成功后，先观察三件事：

  • 方法返回的是 Movie，不是 String。
  • 业务代码没有出现 ObjectMapper 或 JSON.parse。
  • 模型如果返回多余字段，通常不会导致解析失败（框架默认忽略未知字段）。

第二步：看框架如何生成 JSON Schema

ServiceOutputParser 会从返回类型推导 JSON Schema，并生成给模型的格式说明。 但这里有一个关键前提：模型要支持 JSON Schema 响应格式。

模型能力框架行为
支持 RESPONSE_FORMAT_JSON_SCHEMA把 schema 作为响应格式发给模型
不支持退化为「在提示词里追加格式说明」，再解析返回文本

所以同一段代码在不同 provider 上表现可能不同：支持 schema 的模型更稳定， 不支持的模型更依赖提示词和解析器的容错。

第三步：处理列表、枚举与嵌套对象

结构化输出不只支持扁平对象。下面三种结构很常见： 

enum Genre { SCI_FI, DRAMA, COMEDY }

record Actor(String name, String role) {}

record Movie(
        String title,
        int year,
        Genre genre,
        List<Actor> actors) {}

框架会为枚举生成约束，为列表生成数组 schema，为嵌套 record 递归生成对象 schema。 重复类型会生成 $ref / definitions，支持递归结构。

字段名就是模型看到的字段名

用 f1、f2 这种名字，模型只能猜含义。给字段加 @Description（dev.langchain4j.model.output.structured.Description）， 比在提示词里重复解释更稳。

第四步：解析成功不等于业务正确

框架负责「JSON → 对象」，但不负责「年份不能是 1800」「金额必须大于 0」。 先做最简单的业务校验： 

Movie movie = assistant.recommend("科幻");

if (movie.year() < 1900 || movie.year() > 2100) {
    throw new IllegalStateException("模型返回了不合理年份：" + movie.year());
}

需要自动重试时，可以用输出护栏（OutputGuardrail）： 护栏失败会返回一条反馈，框架把反馈拼回上下文并重新请求，默认最多重试 2 次。 护栏适合「格式/范围」这类可自动纠正的问题；复杂业务规则仍建议人工或上层服务处理。

第五步：流式场景怎么办

流式 token 不是完整 JSON，不能边收边解析成对象。而且框架在流式模式下不会自动生成 JSON Schema，也不会自动把结果解析成 POJO。

  • 要自动结构化输出：用非流式返回类型。
  • 要流式：返回 TokenStream，在 onCompleteResponse 里拿完整文本，自己解析。
  • 或者先流式展示，再把完整文本交给一个非流式 AI Service 做结构化抽取。

常见错误与排查

1. 解析失败 / JSON 不完整
你会看到
OutputParsingException 或 Jackson 反序列化错误。
因为
模型没有按结构输出，或输出被截断。
改成
确认 maxOutputTokens 够用；在系统提示里强调「只输出 JSON」；给字段加描述。
2. 枚举值不在范围内
你会看到
反序列化失败，提示 unknown enum value。
因为
模型生成了枚举里不存在的值。
改成
减少枚举数量、加描述，或让模型返回字符串后自己映射。
3. 流式接口返回 POJO 失败
你会看到
运行时异常或拿到空对象。
因为
TokenStream 只给完整 ChatResponse，不会自动解析 POJO。
改成
流式返回文本，或改用非流式接口做结构化输出。
4. 模型返回了额外字段
你会看到
大多数情况下不会报错。
因为
LangChain4j 默认忽略未知字段。
改成
如果必须严格，自己配置 ObjectMapper 或做二次校验。

动手练习：从文本到订单对象

把客服助手升级成结构化输出：

  1. 定义 record OrderStatus(String orderNo, String status, String eta)。
  2. 让 AI Service 返回 OrderStatus，而不是字符串。
  3. 给字段加 @Description，让模型知道 eta 是预计到达时间。
  4. 加业务校验：status 只能是 PAID、SHIPPED、DELIVERED。
  5. 进阶：用 OutputGuardrail 对不合法状态自动重试一次。
