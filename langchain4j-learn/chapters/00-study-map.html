00 · 学习地图：LangChain4j 适合谁、和 Spring AI 怎么选

三条学习主线、章节依赖图、前置知识、没有 API Key 能学到哪，以及 LangChain4j 与 Spring AI 的边界。

为什么要再造一个文档站

官方文档按能力分篇，适合已经知道要查什么的人；但第一次做 Java AI 应用时，真正难的是 「先建哪个对象、消息怎么拼、失败在哪一层」。本站按工程落地顺序重排，并把每个结论回源到 1.23.0 的 Java 源码，方便你在 IDE 里直接跳过去。

本站的默认假设

JDK 17、Maven、一个 OpenAI 兼容端点（DeepSeek 或 Ollama）。示例不绑定 Spring， 但会标出与 Spring Boot starter 的差异。

三条学习主线

① 跟做线

  • 01 章先跑通一次 chat()
  • 02–04 章把模型、消息、AI Service 拆开
  • 每段代码都能单独复制运行

② 理解线

  • 看接口契约：ChatModel / StreamingChatModel
  • 看请求对象：ChatRequest 与 ChatResponse
  • 看 AI Service 如何把接口方法翻译成模型调用

③ 避坑线

  • 每章末尾给「你会看到 X → 因为 Y → 改成 Z」
  • 重点标出 0.x 到 1.x 的 API 变化
  • 明确稳定版与 beta 版的边界

章节依赖图：为什么是这个顺序

  1. 01 环境
    先让 classpath 正确，再谈 API。
  2. 02–03 模型与消息
    ChatModel 是最小契约，消息是它的输入输出。
  3. 04–06 AI Service、结构化输出、工具
    声明式接口把前两章包起来，工具是模型与 Java 的边界。
  4. 07–08 记忆与 RAG
    多轮与知识库都需要「消息 + 检索」这两块地基。

前置知识自查

  • 会写 Maven 的 pom.xml，知道 dependencyManagement 是什么
  • 能读懂 Java 泛型、List<T>、Optional 与 record
  • 知道 HTTP 401 / 429 大概是什么意思
  • 不要求 Spring 经验；有 Spring 经验会更容易理解自动装配

没有 API Key 能学到哪一步

没有 Key能做什么
01 章编译、看依赖树、理解模块划分
02–03 章构造 ChatRequest、PromptTemplate，用假模型跑消息流
04–08 章读接口与源码；真正调用模型需要 Key 或本地 Ollama

事实来源与版本承诺

全书对应 LangChain4j 1.23.0、JDK 17。稳定模块版本是 1.23.0，实验模块是 1.23.0-beta33，BOM 会分别管理 pom.xml:13。 JDK 要求见 pom.xml:39。
