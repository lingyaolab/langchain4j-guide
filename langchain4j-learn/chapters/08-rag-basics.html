08 · RAG 基础：加载、切分、Embedding 与检索

DocumentLoader、DocumentSplitter、EmbeddingModel、EmbeddingStore、EmbeddingStoreIngestor、ContentRetriever。

读完你能做到

  • 把文件加载成 Document 并切分成 TextSegment
  • 选一个 embedding 模型并理解维度
  • 把向量写进 EmbeddingStore
  • 用 ContentRetriever 把召回内容拼进 AI Service

先说为什么：RAG 是 ETL + 检索 + 拼装

它不是一个类，而是一条流水线：加载文档 → 切分 → 向量化 → 入库 → 查询时召回 → 拼进提示词。 LangChain4j 把这些步骤拆成可替换的接口，方便你换解析器、切分器、向量库。

四段流水线：加载、切分、向量化、入库

DocumentSplitter：按字符、段落与 token

DocumentSplitter splitter = DocumentSplitters.recursive(500, 50);
List<TextSegment> segments = splitter.split(document);

两个参数是字符数：每段最多 500 字符，重叠 50 字符。切分粒度直接影响召回质量： 太小会丢上下文，太大会挤占提示词预算。按 token 切分要用三参数重载并传 TokenCountEstimator。

EmbeddingStore：内存与 pgvector

InMemoryEmbeddingStore 适合测试；生产常用 pgvector、Milvus、Qdrant 等。 store 的职责是保存向量与原文，并支持按相似度检索。

EmbeddingStoreIngestor：一条龙入库

EmbeddingStore<TextSegment> store = new InMemoryEmbeddingStore<>();

EmbeddingStoreIngestor ingestor = EmbeddingStoreIngestor.builder()
        .documentSplitter(DocumentSplitters.recursive(500, 50))
        .embeddingModel(embeddingModel)
        .embeddingStore(store)
        .build();

ingestor.ingest(document);

ContentRetriever 与 RetrievalAugmentor

ContentRetriever retriever = EmbeddingStoreContentRetriever.builder()
        .embeddingStore(store)
        .embeddingModel(embeddingModel)
        .maxResults(4)
        .minScore(0.6)
        .build();

Assistant assistant = AiServices.builder(Assistant.class)
        .chatModel(model)
        .contentRetriever(retriever)
        .build();

每次调用前，框架会用用户问题召回若干 Content，拼进提示词。 maxResults 默认 3、minScore 默认 0.0。

陷阱与窍门

换了 embedding 模型却没重建索引

维度或语义空间变了，旧向量不可用；必须全量重算。

minScore 设得太高

召回为空时模型只能瞎答；先看召回条数，再调阈值。
