08 · RAG 基础：让模型回答你的资料

模型不知道你的退款政策、内部文档、订单规则。RAG 的做法是：先把资料切成片段、转成向量存起来； 用户提问时先检索相关片段，再把这些片段一起交给模型回答。这一章用一份退款文档走完整条链路， embedding 用本地模型，不需要额外 API Key。

学完这一章，你能做什么

  • 把一份 Markdown / 文本文件加载成可检索的片段
  • 用本地 embedding 模型把文本转成向量
  • 把向量存进内存向量库，并完成一次相似度检索
  • 把检索接进 AI Service，让回答基于你的资料

先理解：RAG 解决的是模型不知道你的资料

你直接问模型「退款要几天」，它可能给你一个通用答案，甚至编一个数字。 因为你的退款政策不在它的训练数据里。RAG 不重新训练模型，而是在提问时把相关资料递给它： 

用户问题 + 检索到的资料片段 → 模型 → 基于资料的回答

它不是「让模型变聪明」，而是「给模型开卷考试」。资料的质量、切分粒度、检索参数， 直接决定回答质量。

第一步：把一份文档变成可检索的片段

整条链路分五段，先记住这个顺序：

阶段做什么本章用什么

切分Document → TextSegmentDocumentSplitters.recursive

入库向量 + 原文 → EmbeddingStoreInMemoryEmbeddingStore
检索问题 → 相关片段EmbeddingStoreContentRetriever

第二步：加载文档

先准备一份 docs/refund.md，内容随意，只要是你的业务资料。然后加载： 

Document document = FileSystemDocumentLoader.loadDocument(
        Path.of("docs/refund.md"),
        new TextDocumentParser());

加载器只负责把文件读成 Document；PDF、Word、网页需要换对应的 parser / loader。 本章先用纯文本，避免一开始就卡在格式上。

FileSystemDocumentLoader.java:49

第三步：切分文档

DocumentSplitter splitter = DocumentSplitters.recursive(500, 50);
List<TextSegment> segments = splitter.split(document);

两个参数是字符数：每段最多 500 字符，相邻段重叠 50 字符。 重叠是为了避免一句话被切断后语义丢失。按 token 切分要用三参数重载并传 TokenCountEstimator。

切太大或太小都不好

太小：一段话被切碎，检索到了也缺上下文；太大：一次塞进太多无关内容，挤占提示词预算。 先用 300–800 字符起步，再根据召回效果调。

DocumentSplitters.java:45

第四步：把文本变成向量

向量化模型把文本映射成一个数字数组，语义相近的文本距离更近。 本章用本地模型，第一次运行会下载模型文件： 

EmbeddingModel embeddingModel = new AllMiniLmL6V2EmbeddingModel();

这个模型输出 384 维向量。写入向量库前必须确认维度一致；换模型就要重建索引。 不想下载本地模型时，也可以换成 OpenAI / DashScope 的 embedding 模型。

EmbeddingModel.java:39

第五步：把向量存起来

EmbeddingStore<TextSegment> store = new InMemoryEmbeddingStore<>();

内存库适合学习和测试，重启就清空。生产环境常用 pgvector、Milvus、Qdrant 等； 接口相同，换实现即可。

EmbeddingStore.java:27

第六步：用一条龙入库

EmbeddingStoreIngestor 把「切分 + 向量化 + 入库」串起来，省得手动循环： 

EmbeddingStoreIngestor ingestor = EmbeddingStoreIngestor.builder()
        .documentSplitter(splitter)
        .embeddingModel(embeddingModel)
        .embeddingStore(store)
        .build();

ingestor.ingest(document);

入库是离线任务。文档变更后重新跑这一段，不要在每次用户提问时重新解析整份文档。

EmbeddingStoreIngestor.java:54

第七步：把检索接进 AI Service

ContentRetriever retriever = EmbeddingStoreContentRetriever.builder()
        .embeddingStore(store)
        .embeddingModel(embeddingModel)
        .maxResults(4)
        .minScore(0.6)
        .build();

SupportAssistant assistant = AiServices.builder(SupportAssistant.class)
        .chatModel(model)
        .contentRetriever(retriever)
        .build();

System.out.println(assistant.ask("退款需要几天？"));

每次调用前，框架会用用户问题检索若干片段，拼进提示词。默认 maxResults 是 3、minScore 是 0.0。 先观察召回条数与分数，再调阈值。

常见错误与排查

1. 回答完全没有用资料
你会看到
模型还是给通用答案。
因为
忘了配 contentRetriever，或检索为空。
改成
先打印检索结果；确认 maxResults 不太小、minScore 不太高。
2. 维度不匹配
你会看到
入库或查询时报向量维度错误。
因为
embedding 模型换了，但索引还是旧维度。
改成
换模型后全量重建索引；本地模型是 384 维，OpenAI 常见 1536 维。
3. 召回片段缺上下文
你会看到
检索到了关键词，但回答断章取义。
因为
切分太小，或重叠不够。
改成
增大段长/重叠，或按标题/段落切分。
4. 每次请求都重新入库
你会看到
第一次回答很慢，CPU/网络飙升。
因为
把加载、切分、embedding 放在了请求路径里。
改成
入库放离线任务；请求只做检索与生成。

动手练习：做一个退款政策问答

  1. 写一份 1–2 页的 refund.md，包含退款条件、时限、所需材料。
  2. 用本章代码完成加载、切分、入库。
  3. 问三个问题：一个答案在文档里、一个不在、一个需要跨两段。
  4. 打印每次召回的片段与分数，观察 minScore 的影响。
  5. 进阶：把 InMemoryEmbeddingStore 换成 pgvector，重启后验证索引还在。
判断自己学会了没有

如果你能解释「为什么要先切分再向量化」，并能根据召回结果调整段长与阈值， 这一章就过关了。
