langchain4j-core / langchain4j / 各 provider 模块的分工与阅读顺序。

模块总览

模块职责
langchain4j-core契约与数据模型：ChatModel、消息、Embedding、Document、RAG 接口与默认检索/增强实现
langchain4jAI Services、Memory 实现、文档加载/切分与 RAG 接线
langchain4j-open-aiOpenAI 兼容的 chat / embedding / image 模型
langchain4j-ollama本地 Ollama 模型
langchain4j-pgvectorpgvector 向量库
langchain4j-mcpMCP 客户端；服务端用 langchain4j-community-mcp-server

langchain4j-core：契约与默认实现

先读 dev.langchain4j.model.chat 与 dev.langchain4j.data.message： 它们定义一次调用最基本的输入输出。再看 dev.langchain4j.store.embedding 与 dev.langchain4j.rag，理解 RAG 的接口边界。

RAG 相关模块

langchain4j-core 放 DocumentLoader、DocumentSplitter、 EmbeddingStore、ContentRetriever 与 EmbeddingStoreIngestor； langchain4j 放 FileSystemDocumentLoader、DocumentSplitters，并负责接线。

provider 与扩展模块

每个 provider 一个模块，通常只实现 core 的接口；向量库、文档解析器、协议也按模块拆。 读源码时先看模块的 pom.xml 依赖，再看入口类的 builder。
