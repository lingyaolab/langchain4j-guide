B · 报错速查：看到什么错，改什么地方

依赖冲突、模型解析、401/429、工具参数、RAG 空召回与流式错误。

怎么用这一页

先按错误文本定位阶段：构建、模型调用、工具、RAG。每条都给「你会看到 → 因为 → 改成」， 并尽量标出源码位置。

构建与依赖

1. NoSuchMethodError / NoClassDefFoundError
你会看到
启动或第一次调用时抛链接错误，类名是 LangChain4j 的。
因为
各模块版本不一致，常见于只升级了 core 没升级 provider。
改成
用 langchain4j-bom 管版本，模块不写版本号。

模型与调用

2. 401 Unauthorized
你会看到
第一次 chat() 就失败，错误体里带 401。
因为
API Key 为空、过期或环境变量没传进进程。
改成
打印 System.getenv("DEEPSEEK_API_KEY") 是否为空；不要在代码里硬编码。
3. 404 / 模型不存在
你会看到
HTTP 404，或服务端返回 model not found。
因为
baseUrl 少了 /v1，或 modelName 不是服务端认的名字。
改成
按厂商文档补全 URL；用 ollama list / 控制台确认模型名。

工具与结构化输出

4. 模型不调用工具
你会看到
回答很正常，但工具一次都没执行。
因为
工具描述太模糊、参数没有 @P、或模型不支持 function calling。
改成
把工具描述写成「什么时候用、输入是什么、返回什么」；先用明确指令测试。
5. 结构化输出解析失败
你会看到
OutputParsingException 或 JSON 反序列化错误。
因为
模型返回了 markdown 围栏、缺字段或枚举值不在范围内。
改成
在系统提示里要求「只输出 JSON」；给字段加描述；对失败做有限次重试。

RAG 与向量库

6. 召回为空
你会看到
模型说「资料中没有」，但文档明明入库了。
因为
切分太大/太小、embedding 模型不一致、minScore 太高。
改成
先把 minScore 降到 0，打印召回条数与分数，再调阈值。
