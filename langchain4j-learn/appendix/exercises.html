F · 动手练习答案：每章做完怎么对照

这不是标准答案，而是「参考实现 + 检查点」。同一道练习可以有不同的写法， 重点是你能不能解释每一步为什么这样做。建议先自己写，再对照。

怎么用这份答案

  • 先跑通自己的版本，再对照参考实现，不要直接抄。
  • 重点看「检查点」：它们比代码更能说明你有没有理解。
  • 如果代码能跑但检查点答不上来，回到对应章节重读。

第 01–02 章：环境与多轮对话

参考实现：一个带系统提示、多轮历史、参数控制的命令行助手。

Scanner scanner = new Scanner(System.in);
List<ChatMessage> history = new ArrayList<>();
history.add(SystemMessage.from("你是 Java 助教，回答不超过 100 字"));

while (true) {
    System.out.print("你：");
    String input = scanner.nextLine();
    if ("exit".equalsIgnoreCase(input)) break;

    history.add(UserMessage.from(input));
    ChatResponse response = model.chat(ChatRequest.builder()
            .messages(history)
            .parameters(ChatRequestParameters.builder()
                    .temperature(0.3)
                    .maxOutputTokens(200)
                    .build())
            .build());

    String answer = response.aiMessage().text();
    System.out.println("AI：" + answer);
    history.add(AiMessage.from(answer));
}

检查点：

  • 能解释「为什么第二轮模型能记得第一轮」：历史消息被一起发送。
  • 能说出 history.add(AiMessage.from(answer)) 不写会怎样：模型记得自己的问题，但不记得自己的回答。
  • 知道 maxOutputTokens 限制的是输出长度，不是上下文长度。

第 03–04 章：提示词与 AI Service

参考实现：用模板管理客服提示，用 AI Service 收口。

interface SupportAssistant {
    @SystemMessage("""
            你是电商客服。
            今天是 {{current_date}}。
            只根据已知信息回答，不超过 80 字。
            """)
    @UserMessage("用户问订单 {{orderNo}}：{{question}}")
    String ask(@V("orderNo") String orderNo,
               @V("question") String question);
}

SupportAssistant assistant = AiServices.builder(SupportAssistant.class)
        .chatModel(model)
        .chatMemory(MessageWindowChatMemory.withMaxMessages(10))
        .build();

检查点：

  • 多个参数必须用 @UserMessage + @V，不能靠顺序。
  • current_date 是框架自动注入的，不需要手动传。
  • AI Service 的返回类型决定解析方式；返回 String 就是纯文本。

第 05–06 章：结构化输出与工具

参考实现：返回订单对象，并用工具查询真实状态。

record OrderStatus(
        @Description("订单号") String orderNo,
        @Description("状态：PAID / SHIPPED / DELIVERED") String status,
        @Description("预计到达时间，ISO-8601") String eta) {}

interface OrderAssistant {
    @UserMessage("查询订单 {{orderNo}} 的状态")
    OrderStatus query(@V("orderNo") String orderNo);
}
class OrderTools {
    @Tool("按订单号查询订单状态，只读")
    OrderStatus queryOrder(@P("订单号") String orderNo, InvocationContext ctx) {
        String userId = String.valueOf(ctx.chatMemoryId());
        return orderService.find(userId, orderNo);
    }
}

检查点：

  • 能解释「解析成功不等于业务正确」：状态值/年份仍要自己校验。
  • 工具返回值会被序列化；不要返回密码、完整手机号。
  • 用户 id 来自 chatMemoryId()，不能让模型填。
  • 同步模式下多工具默认顺序执行；要并发才加 executeToolsConcurrently()。

第 07–08 章：记忆与 RAG

参考实现：多用户记忆 + 退款政策检索。

interface SupportAssistant {
    String chat(@MemoryId String userId, @UserMessage String question);
}

SupportAssistant assistant = AiServices.builder(SupportAssistant.class)
        .chatModel(model)
        .chatMemoryProvider(id -> MessageWindowChatMemory.withMaxMessages(10))
        .contentRetriever(retriever)
        .build();

检查点：

  • @MemoryId 不同，记忆不串；相同 id 才共享历史。
  • 窗口满时优先保留 system 消息；工具结果和对应 AiMessage 一起淘汰。
  • 切分单位是字符数（两参数重载），500/50 表示段长/重叠。
  • 换 embedding 模型必须重建索引，否则维度不匹配。

第 09–10 章：RAG 进阶与 Agent

参考实现：多知识库 + 重排的链路骨架。

RetrievalAugmentor augmentor = DefaultRetrievalAugmentor.builder()
        .queryTransformer(new CompressingQueryTransformer(model))
        .queryRouter(new DefaultQueryRouter(docsRetriever, ticketsRetriever))
        .contentAggregator(ReRankingContentAggregator.builder()
                .scoringModel(scoringModel)
                .maxResults(6)
                .build())
        .build();

Agent 练习的参考结构：

  1. Writer 写初稿，outputKey="story"。
  2. Editor 读 story，改写后仍写 story。
  3. sequenceBuilder 串起来；并行检查分别写 facts / style。
  4. 汇总 Agent 读两个键，决定是否重写。

检查点：

  • 多查询 + 重排必须配 querySelector，否则重排报错。
  • 并行不自动汇总，必须有 Agent 写汇总键。
  • 循环必须设 maxIterations；只设退出条件可能无限循环。

第 11–15 章：MCP、观测、生产化与迁移

MCP 练习的参考链路：

McpClient mcpClient = DefaultMcpClient.builder()
        .key("everything").transport(transport).build();

McpToolProvider provider = McpToolProvider.builder()
        .mcpClients(mcpClient)
        .filterToolNames("get_issue", "list_issues")
        .build();

观测与生产化检查点：

  • 监听器挂到模型上才会触发；流式模型要单独挂。
  • tokenUsage() 可能为 null；指标要有降级值。
  • 只重试 429/5xx；写工具重试前确认幂等。
  • 同步与流式模型不能同时配；返回 TokenStream 只配 streamingChatModel。
  • 从 Spring AI 迁移时，先准备回归集，再按行为重写 RAG/Advisor。
